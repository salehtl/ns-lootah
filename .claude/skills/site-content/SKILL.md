# Content, languages and the CMS

## Where words live

- Page copy: `src/content/copy/<locale>/<page>.json`, one file per page plus `site.json` (header, footer, firm
  details, CTA). The English files define the shape; every locale must match it key for key.
- Repeated content: content collections in `src/content/<collection>/<locale>/*.md` with a schema in
  `src/content.config.ts`. The template has `services`; `src/lib/services.ts` fails the build if locales differ.
- Labels editors shouldn't touch (screen-reader names, number wording such as "Three" / «ثلاث خدمات») stay in code:
  `src/i18n/ui/en.ts`, `ar.ts`, merged by `src/i18n/ui/build.ts`.
- `{placeholders}` in copy (`"Call {phone}"`) are filled in `build.ts`. `[Brackets]` mean "client to supply".

## The CMS contract

`public/admin/config.yml` is generated by `scripts/cms-config.ts` from the English copy files. After adding,
renaming, removing or restructuring a key, run `bun run cms` and commit both.

In `scripts/cms-config.ts`:

- `pages` names each copy file for editors. A new copy file must be added here or the script throws.
- `labels`, `hints`, `pathHints` make field names readable. Name things the way the client talks.
- `shared` lists paths set once and copied to every language (`i18n: "duplicate"`): numbers, URLs, anything
  language-neutral. Without it an editor has to type the number twice and the languages drift.

When the copy's shape changes, tell the user: anyone with `/admin` open must reload before saving, or the stale tab
writes the old shape back. Guard against it where a bad save would blank the live site: validate the shape at build
time and throw a message editors understand (see the `facts` check in `src/views/HomePage.astro`). A failed build
keeps the last good version live.

When the user says something is missing from the CMS, check the generated config has the field, then check whether
the value is hard-coded in a view instead of read from copy. Move it into copy (and `shared` if it's
language-neutral), regenerate, and confirm the build output is unchanged except where intended (diff `dist/` before
and after).

## Removing or adding text

Remove a piece of copy completely: the markup in the view, the key in every locale's JSON, any label in
`cms-config.ts`, then `bun run cms`. Renumber staggered `--i` entrance delays if you removed an animated item.

## Writing copy

- Plain, specific, short. No marketing filler. Keep the client's own terms (if they say "legal consultancy", never
  "law firm"). Some wording has legal weight (who can appear in court, licensed titles, regulated words): flag it
  and ask rather than guess.
- Place names: use the ones the client approves. Record any "never say X" rule in project memory.
- Arabic: Modern Standard Arabic, natural not literal; Western digits (0–9); Arabic brackets for placeholders
  (`[رقم الهاتف]`); counted nouns need the right number agreement (see `areaCount` in `ar.ts`). If you can't write
  a language well, leave a bracketed placeholder and say so.
- Short "accent" lines set in the other language (`accent` keys) are decorative; keep them brief.

## Languages

Languages are defined once in `src/i18n/locales.ts` (name, `dir`, Open Graph locale); `astro.config.mjs` and the
CMS config read it. Read `references/languages.md` for dropping Arabic (single-language site) or adding a language.

## Check

`bun run build` (it validates collections and shapes), then look at the changed pages in every language
(`site-qa`). Commit with a message that says what changed for a reader of the site.
